# v0.1.2 Launch Fix versus v1.0.0 session2 — integration compatibility

## Evidence / scope

The supplied `ShittyFriends-iOS-v0.1.2-Launch-Fix(1).zip` is **not the same source tree**
as the v1.0.0 session2 signing-fix ZIP. Both are native SwiftUI app projects with
`com.sakara.shittyfriends` and use CloudKit, but they are **distinct implementations**.

| Aspect | v0.1.2 Launch Fix | v1.0.0 session2 base |
|---|---|---|
| iOS minimum | 17 | 18 |
| Project | Checked-in `.xcodeproj`, generated with `scripts/generate_project.py` | `project.yml`, generated by XcodeGen |
| App architecture | `App/AppStore.swift`, `Services/CloudService.swift` | `ShittyFriends/App/AppModel.swift`, `Services/CloudKit/CloudSync.swift` |
| Notification service extension | None | `NotificationService` and its own bundle ID/profile |
| Test pipeline | `verify-ios` and `testflight`, Xcode 26.6 | `ios-check` and `ios-testflight`, Xcode `latest` |
| Apple signing | Developer Portal integration + `ios_signing` + Code Signing Identities | Previously CLI `fetch-signing-files` with four env vars |

## Safe adaptation applied to v1.0.0

- Adopted `integrations.app_store_connect: shittyfriends` from v0.1.2.
- Adopted `environment.ios_signing` selection of stored App Store profiles; the
  main bundle identifier also matches profiles for embedded extensions.
- Preserved v1.0.0 app AND `NotificationService` targets; these require **two**
  profiles with the correct capabilities.
- Replaced `publishing.app_store_connect` inline credentials with `auth: integration`.
- Removed `fetch-signing-files`, `keychain initialize`, and `keychain add-certificates`
  steps and the env-var preflight (not applicable to an integration workflow).
- Made build-number API/auth failures fatal rather than treating them as build 0.

## Why the v0.1.2 launch change was not copied

In v0.1.2 `CloudService` creation was made lazy to prevent an unsigned
simulator launch from constructing `CKContainer` too early. In v1.0.0
`AppModel.init` constructs a `CloudSync` object but its initializer only loads
local state; `CKContainer` is accessed via a deferred `CloudSync.container`
computed property / `CloudConfig.container` when `CloudSync.start()` runs.
`CloudSync.start()` has an XCTest guard. Changing this to mimic v0.1.2's
`AppStore.cloud` lazy property is therefore **not a compatible textual port**.
Similarly, the v0.1.2 `test_ios.sh` runner targets a different scheme and project
layout; do not paste it into the XcodeGen source tree without its own review.

## Validation status

This is a **Codemagic signing configuration change**, not proof of an Apple-signed
build. The actual integration, certificate, provisioning profiles, Apple API access,
CloudKit schema, simulator runs, Xcode compile, and IPA export must be verified on
Codemagic / in the Apple portal. No private credentials are in the ZIP.

See `docs/SETUP.md` for the exact two-profile setup and required integration name.
